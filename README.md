# FullProof · 수사행위 검증 시연

**수사했다는 기록이 아니라, 수사했다는 증거.**

실종사건 한 건의 수사기록(Claim)과 가상 기관 기록(Proof)을 대조하고, 증거 보존기한과 관리자 확인 흐름을 체험하는 React 웹 프로토타입입니다. BLOCK AI 26 · 팀 AIF4.

## 바로 실행

Node.js 20.19 이상 권장(이 산출물은 Node 24에서 검증).

```sh
npm ci
npm run dev
```

화면에 표시되는 로컬 주소를 엽니다. 기본 실행은 API 키·지갑·블록체인 노드 없이 동작합니다.

```sh
npm test
npm run build
npm run preview
```

## 3분 시연

1. **정상 검증**: STEP 01의 입력과 기관 기록을 대조합니다. `전체 5단계 검증` → `관리자 확인으로` → 확인 사유 입력 → `최종 종결 승인` → 확인합니다.
2. **기록 불일치**: 두 번째 시나리오를 선택한 뒤 전체 검증합니다. STEP 01의 발신 기록 부존재와 관리자 화면의 종결 제한을 확인합니다. 사유를 저장해도 불일치는 검증 완료로 바뀌지 않습니다.
3. **CCTV 기한 임박**: 세 번째 시나리오를 선택해 STEP 04를 검증합니다. 미확보 CCTV 3건·잔여 12시간 경고를 확인합니다.
4. **직접 입력 실험**: 정상 시나리오에서 대상자 ID를 `P-9999`로 바꾸거나 시각을 `19:00`으로 바꾸고 다시 검증합니다. 입력 변경 시 이전 검증 결과가 무효화되는 것도 확인할 수 있습니다.
5. **검증 이력**: 결과·대조 근거·SHA-256·관리자 확인 사유를 확인하고 JSON으로 내려받습니다.

모든 사건·인물 식별자·기관·시간·증거는 시연용으로 만든 가상 데이터입니다. 실제 사건의 수사기록을 재현한 데이터라고 주장하지 않습니다. 시연 기준 시각은 2026-09-13 19:00 KST로 고정되어 날짜가 지나도 기한 시나리오를 재현할 수 있습니다.

## 구현 범위 — 제출 시 그대로 구분하세요

| 기능 | 상태 |
|---|---|
| 5개 수사 STEP·3개 시나리오·직접 입력 | 구현 |
| 대상·행위·기관 코드·시각·완료 여부 규칙 검증 | 브라우저에서 실제 계산 |
| 기록 부존재 / 미응답 / 미완료 / 기한 임박 / 기한 경과 구분 | 구현 |
| 종결 조건 확인·관리자 사유·최종 확인 | 시연 세션에서 구현 |
| 검증·확인 기록 해시와 이전 해시 연결·JSON 다운로드 | 브라우저 세션에서 실제 계산 |
| 로컬 검증 API 연결 | 선택 실행, 동일 엔진 재사용 |
| LLM 자연어 구조화·의미 대조 | 미연결. 메모는 저장만 하며 구조화 필드로 검증 |
| 기관 전자서명·기관 진위 검증 | 미연결. 기관 코드는 일치만 검사 |
| 블록체인 Proof Registry·트랜잭션 | 미연결. 거래 해시나 배포 성과를 만들어 표시하지 않음 |
| 사용자 인증·공유 DB·영구 보관 | 미구현. 실제 수사 업무에 사용할 수 없음 |

기록은 탭 메모리에서만 유지됩니다. 새로고침·시연 초기화·시나리오 전환 시 사라집니다. 내려받은 JSON과 SHA-256은 블록체인 증명 또는 원천기관 서명 증명이 아닙니다. 관리자의 사유 저장은 누락된 증거를 대체하지 않습니다.

## 제공 코드와의 관계

제공된 `ai_engine.py`의 대상·행위·시간·수행 결과 검사 구조를 `src/engine.js`로 옮겨 시연에 연결했습니다. 기존 문제였던 실패 기록의 완료 처리, 기한 경과/임박 혼동, 빈 필수 절차의 종결 통과를 방지했습니다. 기관 코드 일치 검사는 전자서명 검증을 대신하지 않습니다.

기존 FastAPI `/api/v1/cases/verify`는 자연어 Claim을 받아 LLM을 호출하는 다른 계약입니다. 현재 사이트는 그 서버에 연결됐다고 주장하지 않으며, 출처가 확인되지 않은 `SUPPORTED` 값을 그대로 온체인에 보내지 않습니다. 원본 ai_engine.zip / chain-of-investigation.zip은 수정하지 않았습니다.

## 선택 사항: 로컬 API로 실행

첫 터미널:

```sh
npm run demo:api
```

`.env.example`을 `.env.local`로 복사해 다음 값을 설정한 후 두 번째 터미널에서 `npm run dev`를 실행합니다.

```dotenv
VITE_VERIFICATION_API=/api/v1/demo/verify
```

Vite가 `/api` 요청을 로컬 8000번 서버로 전달합니다. 요청은 `{ step, now }`, 응답은 `{ status, reason, checks, completed, engine, source }`입니다. 이 API 역시 규칙 시연용이며 LLM·기관 시스템·블록체인을 호출하지 않습니다. API 오류 시 고정된 성공 응답으로 바꾸지 않고 오류를 표시합니다.

정적 배포 시에는 `VITE_VERIFICATION_API`를 비워두세요. GitHub Pages와 현재 Sites 정적 배포에는 서버가 포함되지 않습니다. 실제 API를 배포하려면 HTTPS 서버, 인증, 접근 제어, CORS와 데이터 저장 정책을 별도 구현해야 합니다.

## GitHub 제출

이 디렉터리가 독립된 저장소 단위입니다. `node_modules`, `dist`, `.env.local`, `.sites-runtime`과 개인 토큰은 올리지 않습니다. `.github/workflows/deploy.yml`에 GitHub Pages 배포 흐름이 포함되어 있습니다.

1. 팀 GitHub 저장소에 이 폴더의 소스를 올립니다.
2. 저장소 Settings → Pages에서 배포 소스를 GitHub Actions로 설정합니다.
3. main 브랜치의 작업이 성공하면 Pages URL과 이 저장소 URL을 제출 자료에 기재합니다.

현재 환경에서는 특정 팀 GitHub 저장소에 업로드하거나 대회 접수를 대신 제출하지 않았습니다. 실제 저장소 URL과 실제 공개 시연 URL을 확보한 뒤 제출해야 합니다. Sites 미리보기는 기본 소유자 전용이므로 외부 심사자 접근 가능 여부도 확인해야 합니다.
