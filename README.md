# FullProof · 프런트엔드 기초

수사했다는 기록을, 확인 가능한 증명으로.

PPT의 서비스 5단계를 구현한 React 시연용 프런트엔드입니다. 팀 AIF4의 기존 백엔드·AI·블록체인과 연결하기 위한 시작 버전입니다. 현재 공개 저장소의 기존 프런트와 별도 구현이며, 기존 FastAPI와 자동 호환되는 완성본은 아닙니다.

## 실행

Node.js 20.19 이상 권장. Node 24에서 검증했습니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 주소를 엽니다. 기본 시연에는 API 키나 지갑이 필요하지 않습니다.

```sh
npm test
npm run build
npm run preview
```

## 들어 있는 것

- 사건 접수와 사전 정의된 실종사건 템플릿
- 담당자 Claim 입력·저장
- Mock 통신사/CCTV 원천기관 화면 및 시연 증빙 발행
- 기관별 브라우저 시연키 ECDSA 서명·변조 검사
- 대상·행위·기관·시각·완료 상태 규칙 검증
- 정상·기록 불일치·CCTV 보존기한 임박 시나리오
- 관리자 확인·보완 요청·시연 종결
- 세션 내 SHA-256 이력과 JSON 다운로드
- PPT 색상·타이포그래피와 프로젝트 소개

시연: 사건 접수 → 예시 Claim 5개 저장 → 전체 기관 응답 처리 → 전체 5개 규칙 검증 → 관리자 확인.

## 아직 연결되지 않은 것

실제 AI 추천·의미 대조, 기관 인증/Wallet, 기존 FastAPI, EVM 체인, 영구 DB, 암호화 원본 저장소는 연결 전입니다. 기본 실행은 브라우저 내부의 시연입니다.

- 메모의 의미는 검사하지 않습니다. 메모와 별도의 대상/행위/완료 입력값이 다를 수 있습니다.
- 역할별 화면은 실제 로그인/접근 권한 분리를 의미하지 않습니다.
- 시연키와 데이터는 메모리에만 있고 새로고침/시나리오 전환 시 사라집니다.
- 시연 Proof의 서명 범위에 사건 ID·보존기한·확보 상태가 모두 포함되는 것은 아닙니다. 실연동 전에 데이터 모델을 확장해야 합니다.
- 시각은 HH:mm, 기한 계산은 고정 시연 시각 2026-09-13 19:00 KST를 사용합니다.
- 세션 해시 이력은 블록체인 거래가 아닙니다.

기존 테스트 17개는 이 제한된 동작을 검증합니다. 전체 시스템의 보안 또는 AI 정확도 검증을 의미하지 않습니다. 모든 사례는 가상 데이터이며 실제 개인정보를 입력하지 않습니다.

## 파일 구조

```text
src/FlowApp.jsx       5단계 화면과 시연 상태/이벤트 처리
src/flow.css          PPT에 맞춘 반응형 스타일
src/engine.js         시연 데이터·규칙·최종 확인 조건·해시 기록
src/proofs.js         브라우저 시연키와 Proof 서명/검증
server/verify.mjs     선택 실행하는 로컬 규칙 시연 API
public/              표지 이미지·아이콘
tests/               규칙 및 시연 서명 테스트
.github/workflows/   빌드/테스트 CI와 수동 Pages 배포
```

## 선택 실행: 로컬 규칙 API

다른 터미널에서 `npm run demo:api`를 실행하고 `.env.example`을 `.env.local`로 복사하여 아래 주석을 풉니다.

```dotenv
VITE_VERIFICATION_API=/api/v1/demo/verify
```

프런트 개발 서버를 다시 시작합니다. 이 주소는 함께 제공한 Node 규칙 시연 API입니다. 팀 FastAPI의 `/api/v1/cases/verify`와 입력/응답이 다르므로 주소만 바꾸면 연결되지 않습니다. 기본 정적 배포는 이 설정을 비워 둡니다.

## GitHub 커밋과 배포

기존 저장소에 반영하는 방법은 [첫 커밋 안내](HANDOFF.md)를 참고하세요. GitHub에 올릴 파일은 이 폴더 안의 소스 전체입니다. `.git`, `node_modules`, `dist`, 실제 `.env.local`은 포함하지 않습니다.

- push/PR 시 CI가 기존 테스트와 빌드를 수행합니다.
- Pages 배포는 자동 실행하지 않습니다. Settings → Pages에서 GitHub Actions를 선택한 뒤 Actions의 `Deploy to GitHub Pages`를 수동 실행할 수 있습니다.
- GitHub Pages는 정적 프런트만 제공합니다. 백엔드 API는 따로 배포하고 연결해야 합니다.
- 이 소스를 GitHub에 커밋해도 기존 Sites 주소가 자동 갱신되지는 않습니다.
