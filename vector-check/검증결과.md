proofHash: `0xd9491d4f357151184e95ba4f4044686cb93b88daaa62cd6d443614b236ca793b`

EIP-712 Digest: `0x0261a3ca1da9fddfe34b2d0e2643b1f3266b03a17c2d3cf5538074ea3e6e324b`

Python은 rfc8785 0.1.4 / eth-account 0.14.0,
JavaScript는 canonicalize 5.1.0 / ethers 6.17.0을 사용했습니다.
Python 의존성은 상위 .vector-test-deps에 별도 설치했습니다.
JavaScript 의존성은 이 폴더의 package.json / pnpm-lock.yaml에 기록합니다(Node 22 이상).

재실행: 의존성 설치 후 `python check.py`, `node check.cjs`.
각 실행은 기대값 불일치 시 실패로 종료하고 결과 JSON을 저장합니다.
블록체인 접속·서명 생성·서명자 복구는 하지 않았습니다.
Rule Engine 및 운영 서명 코드는 변경하지 않았습니다.

후속 AI 규격 점검에서 common-v11.json과 세 판정 response JSON을 추가했습니다.
양언어 각각 14개 검사가 통과했습니다. 새 common 벡터는 로컬 Rule Engine으로
생성한 합성 데이터이며, 팀 원천기관의 서명 검증을 대체하지 않습니다.
