# 발표자용 사건 대응표

이 표는 발표 준비용입니다. 사건 선택 화면에는 예상 판정을 표시하지 않습니다. 실제 판정은 API 검증 실행 후 결과로 확인하세요.

| 선택 번호 | 화면 사건명 | 내부 사례 | 의도한 확인 흐름 |
|---|---|---|---|
| FP-001 | 중앙공원 실종 신고 | supported | 성공 주장과 기관 연결 성공 증빙 → SUPPORTED |
| FP-002 | 한빛역 실종 신고 | contradicted | 성공 주장과 기관 연결 실패 증빙 → CONTRADICTED |
| FP-003 | 호수마을 실종 신고 | insufficient | 기관 증빙 미확보 → INSUFFICIENT |
| FP-004 | 새봄거리 실종 신고 | ambiguous | 동일 통화 연결 근거 부족 → INSUFFICIENT |

같은 번호로 새 사건을 등록해도 기존 기록을 덮어쓰지 않습니다. 표시 번호 뒤의 회차 식별자로 구분하며 실제 서버 case_id는 유지됩니다. 기존 진행 사례가 있으면 이어 열고, 새 회차가 필요하면 ‘새 사건으로 등록’을 선택하세요.

수사담당자: 사건 선택 → 원문 등록·고정 → AI 추출 → 기관 증빙 확인·연결 → 검증.
원천기관: 해당 사건 → 증빙 준비 → 기관 지갑 서명·기록.
관리자: 검증 근거 확인 → 관리자 확인으로 이동 → 결과 확인/보완/단계 완료 승인 → 서버 조건 충족 시 종결.

알림은 각 역할 화면의 첫 성공 조회 이후 새로 발견한 기록부터 나타납니다. 알림을 시연하려면 수사담당자 화면을 먼저 열어 조회 기준점을 만든 다음 다른 창/탭의 원천기관 화면에서 증빙을 기록하고, 수사담당자 창에서 다음 조회를 기다리세요. 관리자 첫 조회도 마찬가지로 새 검증 기록 생성 전에 열어두세요. 각 창에서는 실제 역할에 맞는 등록 지갑을 사용합니다. 계정 전환 요청은 MetaMask에서 직접 확인해야 합니다.
