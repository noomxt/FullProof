# 알림·검토 화면·사건 선택 개선

2026-10-31. API 전용 연결과 흰색 다크 모드 로고를 유지한 업데이트입니다. 복수 필수 단계 체크리스트 화면은 다시 추가하지 않았습니다. 역할 전환 때 대시보드로 이동하는 방식도 유지합니다.

## 1. 업무 알림

상단 알림 종에서 읽지 않은 기록을 확인합니다. 공식 사건 조회 API를 15초 간격으로 조회하고, 창에 다시 돌아오면 재조회합니다. 동시에 중복 조회하지 않습니다. 첫 성공 조회는 기준점으로 저장하며 과거 기록을 새 알림으로 만들지 않습니다.

- 수사담당자: CONFIRMED 기관 Proof의 새 ID·버전, CONFIRMED 관리자 검토(보완 요청·결과 확인·단계 완료 승인).
- 관리자: CURRENT 및 CONFIRMED인 새 Verification 기록. 이 알림은 별도 검토 요청 제출을 의미하지 않습니다.
- 원천기관: 별도 증빙 제공 요청 API가 확인되지 않아 요청 도착 알림을 만들지 않습니다. 알림 패널에서 해당 제한을 안내합니다.

클릭하면 사건·단계·관련 탭으로 이동합니다. 동일 사건에서 다른 알림을 눌러도 기록을 다시 조회합니다. 알림을 읽는 동작은 서명·승인·거래를 실행하지 않습니다. 조회 실패 시 기존 알림과 읽음 상태를 유지합니다.

알림 기준점·읽음 상태는 환경/체인/컨트랙트/역할별로 이 브라우저에 저장합니다. 서버 알림함·로그인 계정별 알림·기기 간 동기화·모바일 푸시는 아닙니다. 브라우저 저장소를 지우거나 다른 기기에서 처음 열면 새 기준점을 만듭니다. 표시할 알림 이력은 최근 100개입니다. 화면을 닫으면 조회하지 않습니다.

## 2. 관리자 근거 우선

관리자가 사건을 열면 검증 근거 탭부터 표시합니다. 판정·최신성·온체인 상태·충돌 및 부족한 근거 수를 요약하고, 아래에서 원문과 증빙을 비교합니다. 비교에 사용하는 Claim과 Proof는 해당 Verification의 입력 참조 기준입니다. 여러 Proof가 있으면 첫 조회 가능한 Proof를 비교표에 표시하고 전체 참조는 상세로 제공합니다. ‘관리자 확인으로 이동’으로 기존 관리자 확인·보완·승인 화면을 엽니다.

승인 및 사건 종결의 백엔드·컨트랙트 조건은 변경하지 않았습니다. 탭 이동만으로 승인되지 않습니다. 기존 관리자 확인 탭으로 직접 접근하는 것은 막지 않았습니다.

## 3. 업무 정보와 기술 상세

판정·최신성·저장 상태와 업무 근거는 계속 표시합니다. 원문/Proof/Verification 해시, AI 모델·프롬프트, 정책 버전, 기관 서명 데이터, JSON 및 오류 원문은 접힌 상세로 제공합니다. 오류는 간단한 안내를 먼저 보여주며 ‘오류 상세’에서 원문과 정확한 계정·코드를 확인할 수 있습니다. 알 수 없는 사유 코드는 임의 해석하지 않습니다.

## 4. 사건 선택

화면의 선택 카드는 고정 번호와 중립적인 사건명만 제공합니다. 예상 판정을 미리 표시하지 않습니다. 실제 생성된 사건의 서버 ID는 기존 규칙을 유지하고, 사용자 표시용 별칭과 회차 식별자를 사용합니다. 서버 원문·서명·해시는 변경하지 않습니다. 발표자 대응표는 PRESENTER_CASES.md를 참고하세요.

## 실행·테스트

기존과 동일하게 `py configure_ai.py`로 개인 키를 설정한 뒤 `py start_connected.py --live`를 실행합니다. 키 및 .env는 Git에 올리지 않습니다.

- 프론트엔드 테스트 73/73 통과, TypeScript 및 Vite 빌드 통과.
- 새 알림 기준점, 중복 방지, 버전 변경, CONFIRMED 필터, 역할 구분, 일시적 빈 응답, 읽음 유지, 알림 이동, 조회 실패 및 타이머 정리 검증 포함.
- 관리자 근거 우선 진입과 확인 화면 이동, 기술 상세 기본 접힘, 중립적 사건명·표시번호 검증 포함.
- 기존 패키지 대비 백엔드 소스 바이트 불변 확인.
- 이번 수정본으로 실제 Uvicorn·Gemini·MetaMask·Hardhat 전체 E2E 및 브라우저 시각 검사는 실행하지 않았습니다. 테스트 내부의 API 응답은 명시적으로 주입한 fixture입니다. 제품은 Mock으로 전환되지 않습니다.
