# 역할별 화면과 집계

## 화면 분리

| 역할 | 첫 화면 | 사건 업무 메뉴 |
| --- | --- | --- |
| 수사관 | 수사관 업무 대시보드 | 사건 개요·수사 기록·증빙 연결·증빙 비교/검증·검증 이력 |
| 원천기관 | 원천기관 증빙 데스크 | 제공 업무 개요·기관 증빙 제공·제공 이력 |
| 관리자 | 관리자 검토 대시보드 | 검토 개요·검증 근거·관리자 확인·검토 이력 |

역할을 전환하면 해당 대시보드로 이동합니다. 현재 사건은 목록에서 다시 열면 됩니다. URL의 tab을 다른 역할의 업무로 바꿔도 역할 메뉴에 속하는 화면으로 전환합니다. 이는 프론트 업무 UX이며 서버 인증/권한을 새로 구현한 것이 아닙니다. 기관별 데이터 접근 제한은 공식 백엔드에서 별도 구현해야 합니다.

## 검증 카드

‘증빙이 뒷받침하는 검증’은 freshness_status CURRENT이며 CONFIRMED(실제 API) 또는 MOCK(가상 시연)인 SUPPORTED 검증을 집계합니다. 종결 사건도 포함합니다. ‘추가 확인 필요 검증’은 같은 조건의 CONTRADICTED/INSUFFICIENT만 집계합니다. 처리 중·실패·이전 버전 판정은 이 카드에서 제외합니다.

사건 전체의 진실성이나 수사의 적정성을 승인했다는 뜻이 아닙니다. 관리자 확인과 종결은 별도입니다.

## 시연 사례

정상 일치, 결과 불일치, 증빙 부족, 연결 근거 부족을 선택합니다. 기본 동작은 같은 유형의 종결 전 사건을 이어 여는 것입니다. ‘새 시연 회차로 시작’을 선택하거나 같은 진행 사례가 없으면 기존 사건 생성/필수 단계 API를 호출합니다. 삭제·초기화·기존 이력 덮어쓰기는 없습니다.

## 증빙 선택 불편 개선

기록 확인 완료인 증빙을 기본 선택합니다. 대기 중인 증빙 때문에 매핑을 진행할 수 없으면 이유를 버튼 옆에 표시합니다. 원천기관은 기존 PENDING 초안이 있으면 이어서 서명할 수 있게 사용하며, 매번 초안을 중복 생성하지 않습니다. Proof 제공과 실제 열람을 같은 행위로 판단하지 않습니다.

## 디자인

네이비·화이트 기반, 역할별 억제된 블루/그린/골드 포인트, 문서·지문·검증 인장 모티프를 CSS와 Lucide로 구성했습니다. 실제 로고 파일은 변경하지 않았습니다. 다크 테마·모바일·키보드 탐색을 유지합니다. 화면에 새로 도입한 가짜 기관 요청 API나 실제 담당자 배정 데이터는 없습니다.
